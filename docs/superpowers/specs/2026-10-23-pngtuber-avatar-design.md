# Avata-Overlay: ตัวละคร PNGtuber สำหรับสตรีมเกม — Design

วันที่: 2026-10-23
สถานะ: รอผู้ใช้ตรวจ

## เป้าหมาย

สตรีมเกม (MuMu / LDPlayer) โดยไม่มีกล้อง ใช้ตัวการ์ตูนที่ขยับตามเสียงไมค์แทนหน้าจริง แบบ PNGtuber

ขอบเขต spec นี้คือเฟส 0–2:

| เฟส | ได้อะไร |
|---|---|
| 0 | คู่มือติดตั้ง OBS และตั้ง Scene เกม + ไมค์ + ตัวละคร (`OBS-SETUP.md`) |
| 1 | ตัวละครปากขยับตามเสียง กระพริบตา หายใจ แสดงใน OBS ได้ |
| 2 | ปุ่มลัด global เปลี่ยนสีหน้า/เล่นท่า + หน้าตั้งค่าครบ |

**นอกขอบเขต:** ตอบสนองแชท/โดเนท (เฟส 3) ทำเป็น spec แยกเมื่อเฟส 1–2 ใช้งานจริงแล้ว spec นี้แค่กำหนดช่องทางเชื่อมไว้ให้ (ข้อความ `expression` / `action` ทาง WebSocket) ส่วน face tracking, ตัวละครแบบตัดชิ้น (layered) และ Live2D/3D ไม่ทำ

## ข้อจำกัดที่กำหนดการออกแบบ

1. OBS Browser Source ขอสิทธิ์ใช้ไมค์ไม่ได้ จึงต้องให้หน้าที่เปิดในเบราว์เซอร์ปกติเป็นผู้ฟังไมค์
2. ตอนเล่นเกม หน้าต่างที่ถูกเลือกอยู่คืออีมูเลเตอร์ ปุ่มลัดต้องเป็นแบบ global (ดักที่ระดับระบบ)
3. Chrome/Edge ลดความเร็วแท็บที่ถูกย่อหรือไม่ได้เปิดดู การวัดเสียงต้องไม่พึ่ง timer หรือ `requestAnimationFrame` ของแท็บนั้น

## โครงสร้างระบบ

```
 ไมค์ ──► [หน้าควบคุม /studio]  (Chrome/Edge เปิดค้าง)
              │ ระดับเสียง ~30 ครั้ง/วินาที
              ▼ WebSocket
 คีย์บอร์ด ─► [Server Node.js]  ◄── (เฟส 3: ตัวเชื่อมแชท/โดเนท)
 (global)     │ เจ้าของสถานะ + avatar.json
              ▼ WebSocket broadcast
         [หน้าตัวละคร /avatar] ──► OBS Browser Source (พื้นใส)
```

- **Server เป็นเจ้าของสถานะเพียงที่เดียว** หน้าเว็บเป็นผู้ส่งเหตุการณ์หรือผู้แสดงผลเท่านั้น
- รันบน `127.0.0.1` เท่านั้น พอร์ตเริ่มต้น **5180** (Animated-Overlay ใช้ 5173)
- เทคโนโลยี: Node.js ≥ 18 แบบ ESM, `ws` สำหรับ WebSocket, `uiohook-napi` สำหรับปุ่มลัด global, หน้าเว็บเป็น HTML/CSS/JS ล้วน ไม่มีขั้นตอน build
- โปรเจกต์อยู่ใน `Avata-Overlay` แยกจาก Animated-Overlay ใช้รูปแบบเดียวกัน (`start.bat`, `npm start`, `node --test`) และไม่แก้โค้ดของโปรเจกต์เดิม

### หน่วยย่อย

| หน่วย | หน้าที่ | ขึ้นกับ |
|---|---|---|
| `src/server.js` | HTTP static + WebSocket hub, โหลด/บันทึก avatar, broadcast สถานะ | `state.js`, `config.js`, `hotkeys.js` |
| `src/state.js` | สถานะปัจจุบัน: กำลังพูด, สีหน้า, ตัวจับเวลา timed/toggle (pure, ทดสอบได้) | — |
| `src/config.js` | อ่าน/ตรวจ/เขียน `avatar.json` และ `settings.json`, ปฏิเสธค่าที่ผิด, เก็บชุดล่าสุดที่ถูกต้อง | — |
| `src/hotkeys.js` | ห่อ `uiohook-napi`, แปลงชื่อปุ่ม (`F1`, `Ctrl+Alt+H`) เป็นเหตุการณ์; โหลดไม่ได้ก็รายงานแทนการล่ม | `uiohook-napi` |
| `public/shared/voice-gate.js` | ตัดสินว่ากำลังพูดจากระดับเสียง: threshold + เวลาหน่วงปิดปาก (pure) | — |
| `public/shared/frames.js` | เลือกไฟล์รูปจาก (สีหน้า, พูด, หลับตา) ตามลำดับสำรอง (pure) | — |
| `public/shared/renderer.js` | วาดตัวละคร + กระพริบตา + หายใจ + เด้งตอนพูด + ท่า CSS; ใช้ทั้ง `/avatar` และพรีวิวใน `/studio` | `frames.js` |
| `public/avatar/` | หน้าที่ใส่ใน OBS: ต่อ WebSocket แล้วส่งต่อให้ renderer | `renderer.js` |
| `public/studio/` | หน้าควบคุม: ไมค์ (AudioWorklet), ตั้งค่า, อัปโหลดรูป, พรีวิว | `voice-gate.js`, `renderer.js` |

### ข้อความ WebSocket

ทุกข้อความเป็น JSON `{ "type": ..., ... }`

| type | ทิศทาง | ข้อมูล |
|---|---|---|
| `hello` | client → server | `role`: `studio` หรือ `avatar` |
| `voice` | studio → server | `level` (0–1), `talking` (bool) |
| `expression` | studio/hotkey/เฟส 3 → server | `name` |
| `action` | studio/hotkey/เฟส 3 → server | `name` |
| `state` | server → ทุก client | `talking`, `expression`, `avatar` (ชื่อ), `revision` |
| `play` | server → ทุก client | `action` (ท่าที่ต้องเล่นครั้งเดียว) |
| `config` | server → ทุก client | `avatar.json` ฉบับเต็มหลังมีการแก้ |
| `status` | server → studio | สถานะ hotkey, จำนวน avatar ที่เชื่อม, คำเตือน |

server ไม่สนใจข้อความชนิดที่ไม่รู้จัก และไม่ส่งต่อ (forward) ข้อความนั้น

## รูปแบบไฟล์ตัวละคร

สลับรูปทั้งภาพ ทุกรูปเป็นตัวละครทั้งตัว PNG พื้นใส canvas ขนาดเท่ากัน (แนะนำ 1000×1000) และตัวละครอยู่ตำแหน่งเดียวกันทุกรูป

```
avatars/
  my-char/
    avatar.json
    default/   idle.png  talk.png  blink.png  blink-talk.png
    happy/     idle.png  talk.png
```

| ไฟล์ | ใช้ตอน | ถ้าไม่มี |
|---|---|---|
| `idle.png` | เงียบ ตาเปิด | บังคับใน `default`; สีหน้าอื่นใช้ของ `default` |
| `talk.png` | พูด | ใช้ `idle` ของสีหน้าเดียวกัน (ตัวยังเด้ง) |
| `blink.png` | เงียบ หลับตา | ไม่กระพริบตา |
| `blink-talk.png` | พูดและหลับตา | ใช้ `talk` |

ลำดับสำรองของสีหน้า X: `X/ไฟล์ที่ต้องการ` → `X/ไฟล์สำรองตามตาราง` → `default/ไฟล์ที่ต้องการ` → `default/ไฟล์สำรองตามตาราง` → `default/idle.png`

### `avatar.json`

หน้าควบคุมเป็นผู้เขียนไฟล์นี้ ผู้ใช้ไม่ต้องแก้มือ

```json
{
  "version": 1,
  "name": "my-char",
  "expressions": {
    "happy": { "key": "F1", "mode": "timed", "seconds": 4 },
    "angry": { "key": "F2", "mode": "toggle" }
  },
  "actions": {
    "jump":  { "key": "F5" },
    "shake": { "key": "F6" }
  },
  "motion": { "breathe": true, "talkBounce": 8, "blinkEvery": [2, 6] }
}
```

การตั้งค่าที่ไม่ผูกกับตัวละครเก็บใน `settings.json` ที่รากโปรเจกต์ และ `config.js` เป็นผู้ตรวจไฟล์นี้เช่นกัน

```json
{
  "activeAvatar": "my-char",
  "voice": { "threshold": 0.08, "releaseMs": 150, "deviceId": null }
}
```

- ชื่อสีหน้าต้องตรงกับชื่อโฟลเดอร์ และ `default` ห้ามใส่ใน `expressions` เพราะเป็นสีหน้าปกติเสมอ
- `timed`: แสดง `seconds` วินาทีแล้วกลับ `default` ถ้ากดปุ่มซ้ำระหว่างนั้น ระบบจะนับเวลาใหม่ตั้งแต่ต้น
- `toggle`: กดครั้งแรกเปิด กดอีกครั้งกลับ `default`
- ถ้าเปลี่ยนสีหน้าระหว่างที่อีกสีหน้ายังแสดงอยู่ ระบบจะยกเลิกตัวจับเวลาของสีหน้าเดิม
- ท่าที่มีให้ในตัว: `jump`, `shake`, `spin`, `wobble` เป็นแอนิเมชัน CSS ครั้งเดียว ไม่ต้องมีรูปเพิ่ม ถ้าสั่งท่าใหม่ระหว่างที่ท่าเดิมยังเล่นอยู่ ท่าใหม่จะแทนที่ท่าเดิม
- ปุ่มลัดห้ามซ้ำกันภายในไฟล์ (ระบบตรวจตอนบันทึก); หน้าควบคุมแนะนำให้ใช้ F1–F12 หรือปุ่มที่กดคู่กับ Ctrl/Alt เพื่อไม่ให้ชนปุ่มเกม
- การขยับอัตโนมัติ: หายใจด้วยการขยายตัวแนวตั้งประมาณ 2% ทุก 3 วินาที; เด้งขึ้น `talkBounce` px ตอนพูด; กระพริบตาแบบสุ่มทุก `blinkEvery[0]`–`blinkEvery[1]` วินาที นานประมาณ 120ms

## หน้าควบคุม `/studio`

| ส่วน | ทำอะไร |
|---|---|
| พรีวิว | ใช้ renderer ตัวเดียวกับ `/avatar` บนพื้นลายตาราง |
| ตัวละคร | เลือก/สร้างตัวละคร ลากรูปใส่ช่องของแต่ละสีหน้า (server เขียนไฟล์ลง `avatars/<name>/`) |
| ไมค์ | เลือกอุปกรณ์ แถบระดับเสียงสด ลากเส้น threshold ปรับ `releaseMs` |
| สีหน้าและท่า | เพิ่ม/ลบสีหน้า ตั้งปุ่มลัดด้วยการกดคีย์ เลือก timed/toggle ปุ่มทดลอง |
| ขยับอัตโนมัติ | เปิด/ปิดหายใจ ความแรงเด้ง ช่วงกระพริบตา |
| แถบสถานะ | ไมค์ / server / hotkey / จำนวน avatar ที่เชื่อม + ปุ่ม "คัดลอก URL สำหรับ OBS" |

การวัดเสียงใช้ `AudioWorklet` คำนวณ RMS บนเธรดเสียง แล้วส่งค่ามาที่เธรดหลักผ่าน `port.postMessage` ซึ่ง Chrome ไม่ลดความเร็วตอนแท็บถูกย่อ ส่วน `voice-gate.js` ทำงานในตัวรับข้อความนั้น แผนสำรองถ้าทดสอบแล้วยังช้า: ย้ายการฟังไมค์ไปทำใน Node โดยส่งข้อความ `voice` รูปแบบเดิม

## การรับมือข้อผิดพลาด

หลักคือสตรีมต้องไม่มีจอว่างหรือภาพแตก

| เหตุการณ์ | ระบบทำอะไร |
|---|---|
| studio ปิด/หลุด | server ตั้ง `talking=false`; ตัวละครอยู่ท่าเงียบ ยังกระพริบตาและหายใจ |
| server ปิด | `/avatar` แสดงรูปล่าสุดค้าง ต่อใหม่ทุก 2 วินาที; studio ทำแบบเดียวกันพร้อมแถบเตือน |
| ไม่อนุญาตไมค์ / ไมค์หลุด | แถบเตือนสีเหลืองพร้อมวิธีแก้ ลองต่อใหม่อัตโนมัติเมื่ออุปกรณ์กลับมา |
| รูปหาย/เสีย | ใช้ลำดับสำรอง และแสดงคำเตือนใน studio |
| `avatar.json` ไม่ถูกต้อง | ไม่บันทึก แจ้งเหตุผลเป็นภาษาไทย และใช้ชุดล่าสุดที่ถูกต้อง |
| `uiohook-napi` โหลดไม่ได้ | server ทำงานต่อ studio แสดงคำเตือน ปุ่มทดลองบนหน้าเว็บยังใช้ได้ |
| พอร์ต 5180 ถูกใช้ | แสดงข้อความภาษาไทยที่บอกว่าเกิดอะไรขึ้นและวิธีเปลี่ยนพอร์ต (`--port`) แล้วจบโปรแกรม |

## การทดสอบ

**Unit (`node --test`):**
- `voice-gate`: เปิดเมื่อเกิน threshold, ปิดหลัง `releaseMs` เท่านั้น, ไม่กระพริบถี่เมื่อเสียงแกว่งรอบเส้น
- `state`: timed หมดเวลาแล้วกลับ default, กดซ้ำนับใหม่, toggle เปิด/ปิด, เปลี่ยนสีหน้ายกเลิกตัวจับเวลาเดิม
- `frames`: ลำดับสำรองครบทุกกรณีในตาราง
- `config`: ปฏิเสธ `default` ใน expressions, ปุ่มซ้ำ, mode ผิด, ค่าตัวเลขนอกช่วง
- `hotkeys`: แปลงชื่อปุ่มไป/กลับ

**Integration:** เปิด server จริง ต่อ WebSocket แบบ studio และ avatar แล้วตรวจว่า `voice` และ `expression` ได้ `state` ที่ถูกต้อง และเมื่อ studio หลุด `talking` จะกลับเป็น false

**ตรวจด้วยมือ (checklist ใน `OBS-SETUP.md`):**
- พื้นหลังใสใน OBS
- ปากขยับขณะเกมอยู่หน้าสุดและแท็บ studio ถูกย่อ (ดีเลย์ไม่ควรเกินประมาณ 100ms)
- กดปุ่มลัดในเกมแล้วสีหน้าเปลี่ยน
- ปิดแล้วเปิด server ระหว่างอัด ตัวละครกลับมาเอง

## เฟส 0: `OBS-SETUP.md`

คู่มือภาษาไทยทำตามทีละขั้น:
1. ติดตั้ง OBS Studio
2. สร้าง Scene เกมและจับภาพหน้าต่าง MuMu/LDPlayer ด้วย Window Capture
3. ตั้งไมค์ และใส่ฟิลเตอร์ Noise Suppression
4. เพิ่ม Browser Source `http://127.0.0.1:5180/avatar` ขนาด 1000×1000
5. ตั้งค่าสตรีมเบื้องต้น (ความละเอียด, bitrate, encoder)
6. อัดทดลองก่อนไลฟ์จริงตาม checklist ด้านบน
